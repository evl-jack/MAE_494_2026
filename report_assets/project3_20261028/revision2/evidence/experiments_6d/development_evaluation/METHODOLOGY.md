# Grouped development evaluation

This is a development diagnostic of fixed trained models, not a new final test. `protocol.json` freezes the models, data seeds, queries and metrics before generation. No training updates, optimizer, reference-supervised loss or controller tuning is involved. The consumed 3D final-state set and future final seed 991748 are not queried.

There are 6,000 independent relative configurations (seed 991747), each with four equivalent joint representations: canonical, translated, rotated, and translated plus rotated. These give 24,000 joint queries at each of 21 horizons from 0 to 0.5 seconds. Joint poses use a separate seed, 991749. Every pose in a group describes the same physical encounter, so there are 6,000 independent groups, not 24,000 independent encounters. Confidence intervals resample whole groups, after averaging their four absolute prediction errors.

The exact game reduction maps each joint configuration to the original three-state Air3D problem. The unchanged numerical solver provides approximate reference values on 97×97×72 and 129×129×96 grids. It saves direct solutions at each queried horizon; no temporal interpolation is used. Only queried values and gradients are retained, rather than full grids. The relative region and possible physical motion fit within the solver domain, and all joint initial positions plus maximum displacement fit within the absolute training box.

All three new models, plus the fixed 3D 3A and Long22000 models, are evaluated on the same fresh encounters. The 3D predictions are repeated across equivalent poses by construction; their pose consistency is a property of using relative inputs, not a newly learned skill. The main planned comparison is final-horizon value MAE for 4C versus 4B. All candidates are reported, regardless of outcome.

Unsafe means value ≤0. False-safe is a positive prediction where the numerical reference is nonpositive; false-unsafe is the reverse. Both denominators and counts are recorded. Numerical-reference classifications near zero are sensitive to approximation error, so coarse/fine value differences are reported separately. Sampling confidence intervals do not cover solver error or variation across training seeds.

At 0.25 and 0.5 seconds, reference gradients come from central spatial differences and periodic central heading differences on each grid, followed by trilinear interpolation. These are mapped into six joint derivatives by the coordinate chain rule. They are approximate derivatives of the numerical solutions, not exact derivatives of the true value or the derivative of the trilinear value interpolant. An affine/periodic analytic fixture checks the helper's derivative accounting.

Both heading derivatives determine the instantaneous optimal turning choices. The sign-agreement reports require coarse/fine reference signs to agree and both magnitudes to exceed the stated margin (0.005, 0.01 or 0.02 m/rad). They report the number of eligible queries and underlying groups, including an initially separated subset. A sign match tests candidate instantaneous turning decisions; no closed-loop rollout or exhaustive safety verification is included. A six-component gradient cosine mixes different derivative units and is only supplementary; switching coefficients are the control-relevant comparisons.

Finite pose gaps measure translation/rotation consistency. Local gradient identities separately measure sensitivity along physically irrelevant common translation and rotation directions. The heading-alias test shifts one vehicle heading by ±2π only when both representations stay within the sampled heading domain. Terminal equality, the obstacle inequality, the lower physical value bound, and time-monotonicity checks are also recorded. Exact output constraints alone do not guarantee the other properties.

Evaluation executes as a managed process with the existing project interpreter. Training ran in VS Code; this diagnostic does not claim to have run in its debugger. The saved report can be viewed there. Checkpoint and source hashes are verified before and after evaluation.
