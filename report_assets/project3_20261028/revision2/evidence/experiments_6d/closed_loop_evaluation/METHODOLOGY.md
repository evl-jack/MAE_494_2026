# Closed-loop development comparison

The fixed protocol selects 200 relative groups from the already generated development set using seed 991754, without looking at outcomes. All four joint poses are retained, giving 800 initial joint states. Neither old final states nor the unused future final seed is queried. No training, optimizer updates, controller tuning or safety filter is introduced.

Eight policies are tested in both roles: 4A, 4B, 4C, the saved 3D_Long model, numerical reference feedback, straight, constant maximum left turn and constant maximum right turn. The full ordered 8×8 matrix runs at control intervals of 0.01 and 0.005 seconds, totaling 102,400 mathematical trajectories. This is a fixed, finite policy comparison, not an exhaustive search over adversarial strategies.

Every controller receives decreasing time remaining, beginning at 0.5 seconds. Joint PINNs use `u = 3 sign(V_heading_e)` and `d = -3 sign(V_heading_p)`. The relative PINN and reference use the equivalent chain-rule coefficients. Exact zero selects zero turn. No smoothing, deadband or controller-specific adjustment is used. Each heading is canonically wrapped at controller updates; this specifies how the raw-heading networks are deployed, rather than assuming they are periodic.

Reference feedback comes from the unchanged 129×129×96 numerical solve at 21 time planes. Central spatial and periodic heading grid derivatives are interpolated in space and linearly between bracketing times. These are approximate feedback derivatives. Initial labels are reused from the saved coarse/fine development reference, and the regenerated fine solution must reproduce those initial labels within 1e-12 m.

Controls are held constant for each interval, so each vehicle follows an analytically integrated circular arc (or its straight-line limit). No Euler position approximation is used. The code evaluates exact arc separations at nine equally spaced times per interval. The minimum of these sampled distances is an upper bound on the true within-interval minimum. Relative speed is at most 2v, so subtracting `v*dt/8` provides a lower bound (plus a 1e-12 numerical guard): 0.0009375 m at dt=.01, and 0.00046875 m at dt=.005. A sampled distance at or below R establishes a definite geometric contact. If only the lower bound reaches R, contact is possible and the result is flagged as ambiguous. These bounds apply to the fixed sample-and-hold trajectory; they do not certify a continuously updated ideal feedback policy.

The primary comparison is 4C as evader against the reference pursuer at dt=.005, restricted to initially separated groups whose coarse and fine initial values both exceed +0.01 m. The other reported subsets are all initial states and initially separated states. Initial overlap counts as contact at time zero. Trajectories continue mathematically through the horizon after contact, while the contact flag stays absorbing. Minimum separation and switch counts summarize the full mathematical horizon, including post-contact motion; they should not be interpreted as flight behavior after a physical crash.

Raw controls are saved for every step/pair/initial state so the trajectories can be replayed without model queries. Example paths are saved for the first four selected groups and all their poses/policy pairs, rather than choosing favorable examples after seeing outcomes. Reports include definite/possible contact, separation, full-horizon switching, pose consistency, and time-step sensitivity. The worst result across eight tested pursuer policies is a finite-policy stress test, not a bound for all disturbances.

Before running, analytic fixtures check the exact-arc semigroup, zero-turn limit, translation/rotation consistency, between-endpoint collision detection and assignment of all 64 actor-policy pairs. Source hashes, fixed model hashes and input bytes are protected. The diagnostic runs in a managed process with the main project interpreter; training previously ran in VS Code. The result report is saved to all project copies and can be viewed in VS Code.
