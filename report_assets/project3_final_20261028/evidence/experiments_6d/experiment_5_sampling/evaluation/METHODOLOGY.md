# Experiment 5 development evaluation methodology

The training endpoints and original Experiment 5 protocol were frozen before this comparison. The evaluation protocol and 49-policy-pair actor checks were then saved before generating fresh development states or numerical labels. The driver configures the existing, unchanged `evaluate.py` and `rollouts.py` modules with new output paths, seeds and model lists. It replaces only the model loader needed for the three joint-coordinate checkpoints; dynamics, solver, interpolation, metrics, control signs and contact logic remain the existing implementations. Source snapshots and SHA-256 guards record the exact code used.

The fresh development set has 6,000 relative configurations, with each lifted into canonical, translated, rotated, and translated-plus-rotated joint coordinates. The relative box is x,y in [-.6,.6] m and heading in [-pi,pi]. Midpoint shifts are in [-.5,.5] m and rotation angles in [-pi,pi]. The four poses form one statistical group. The models see seven inputs: time-to-go and six joint coordinates. Value predictions are evaluated at 21 horizons from zero to .5 s. Numerical reference labels use the exact reduction to relative coordinates, not a learned 3D model.

Relative-state seed is 991765; pose seed is 991766. The fine reference uses 129x129x96 nodes and the comparison level 97x97x72, on the same spatial domain of half-width 2 m. Both use the unchanged first-order local Lax-Friedrichs solver. Gradients are central differences on each grid followed by trilinear interpolation; these are approximate reference covectors, lifted by the chain rule to joint coordinates. Switching-sign summaries use three fixed coefficient margins, agreement of coarse/fine reference signs, and both all-state and initially separated subsets. Excluded states near switching surfaces can still be important for control.

The primary metric is final-horizon mean absolute value error of 5R versus 5U. All models and horizons, both types of classification error, bias, tails, pose spread, heading aliases, gradient errors and structural constraint checks are retained. The bootstrap resamples relative groups after averaging their four absolute pose errors: 2,000 paired draws with seed 991768. It estimates sampling uncertainty conditional on these checkpoints and this approximate reference; it does not estimate training-seed variability or solver error. No intermediate checkpoint was chosen by accuracy.

A separate uniform physics audit draws the same 8,192 full-domain/full-time points for every model, seed 991769, without forced zero-time rows. It compares the native absolute VI residual on a common distribution. The saved 16,884-point local diagnostic and existing 161/193-grid reference-derived fields are reused only as secondary known-region checks. They are not used for training, candidate selection or choosing checkpoints. The initial known-case turn test makes no new closed-loop claim.

Closed-loop evaluation selects 200 fresh relative groups without replacement with seed 991767, retaining all four poses. The seven policies are parent 4C, 5U, 5R, numerical-reference feedback, straight, constant left and constant right, in both roles: 49 ordered pairs and 800 initial joint states at dt=.01 and .005. This produces 78,400 mathematical trajectories. Each step holds the controls constant and integrates exact independent circular arcs; headings are wrapped at every update. Nine exact-arc samples per interval give definite contact if any separation is at most .25 m. The relative-speed bound gives a lower separation estimate and a possible-contact count, with gap at most v*dt/8 plus roundoff. Halving the control-update interval checks feedback discretization separately.

All trajectories continue mathematically through .5 s after contact; the contact flag remains absorbing. Switch counts cover the entire horizon. The reference-safe subset requires initially separated drones and both reference-grid values above .01 m; its membership is independent of learned predictions. Contacts in this subset are not automatically false-safe predictions by the PINN: initial learned values may already classify those states as unsafe. All policies, all/separated/reference-safe subsets, possible contacts, time-step changes and worst outcomes against this finite pursuer-policy set are saved. This is neither an exhaustive adversarial search nor a safety certificate.

Execution uses managed Python processes with the main project interpreter, CPU and two Torch threads, rather than the VS Code debugger. Reports are opened in VS Code. No optimizer is instantiated, no checkpoint is updated, no reference labels enter training, and the old consumed 3D final states and reserved future final seed 991748 are not queried. Hash checks read protected files only to verify preservation.
