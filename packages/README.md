# Air3D Project 3 — portable research package

This is the completed small-scale DeepReach-style study, including fresh-run code and optional saved models/results. No training starts automatically. Python and dependencies must be installed separately; this is not a bundled Python runtime.

## 1. Install the small code package

Extract project3-20261028-v1-code.zip. It creates project3-portable/. Open a terminal there. Use Python 3.12 (64-bit).

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py verify
.\.venv\Scripts\python.exe run.py check
```

Linux, with Python 3.12 installed:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py verify
.venv/bin/python run.py check
```

The CPU wheel command follows the official PyTorch 2.5.1 installation page: https://pytorch.org/get-started/previous-versions/#v251. CUDA is unnecessary. Windows relocation is tested for this release; Linux commands follow the same dependencies but have not been executed here. macOS is not covered by this CPU-wheel recipe.

`verify` checks installed file hashes. `check` runs small derivative/Hamiltonian fixtures without an optimizer or saved test data. It does not train, build new research comparisons, or open the reserved 6D final set.

## 2. Add saved results when needed

Three optional archives share the same project3-portable/ root:

- relative-results: all saved 3D model checkpoints, histories, source snapshots and Experiment 1–3 artifacts.
- reference-results: grid/reference caches, diagnostic fields and the completed 3D final evaluation, including its already-consumed inputs.
- joint-results: 4A–4C and 5U/5R checkpoints, grouped development values/gradients, collision traces and failure audits.

Download all three ZIPs into the folder containing project3-portable, then run:

```sh
python install_results.py
python run.py verify --all
```

Alternatively, `python install_results.py --download` downloads the three versioned archives from GitHub and checks their SHA256 hashes before extraction. Use your virtual environment's Python for all commands. Standard ZIP extraction also works: extract every archive into the same parent directory so their project3-portable folders merge.

## 3. Query existing models — no training

With result packages installed:

```sh
python run.py predict --model 3d-long --tau 0.5 --state 0.4 0.2 0.3
python run.py predict --model 5U --tau 0.5 --state 0.4 0.2 0.3
```

State arguments are relative x/y in meters and heading difference in radians. Joint-model queries use the equivalent pose with the evader at the origin heading zero. Output is the approximate collision-margin value, not a certified safety decision. No reference solution is generated by these commands.

## 4. Verify archived evidence — no training

Install all optional archives first:

```sh
python run.py verify-results --part report
python run.py verify-results --part training
python run.py verify-results --part evaluation
```

The last command recomputes saved Experiment 5 metrics/bootstrap intervals and replays the saved controls. It uses the existing evaluation arrays, not new encounters, labels or the unused 6D final set. Some original verification scripts rewrite verification JSON in this extracted copy; retain the ZIPs as the original archive. Run `verify --all` before these scripts if you want the original-byte integrity check.

## 5. Run a new setup-training check only when intended

```sh
python run.py train-smoke --train --out work/my_new_smoke_run
```

This explicitly runs the original 60-step smoke configuration. It is a setup check, not a reproduction of the reported accuracy. Without --train the wrapper refuses optimizer updates. Fresh output folders are required. To run larger original configurations, use the explicit --train entry points described in outputs/deepreach/README.md and the phase records; full studies can be expensive. Some frozen phase drivers protect their original output directories and are not generic sweep tools. The portable wrapper supplies a fresh-output training route and read-only checkpoint queries rather than changing those original guards.

## Files, provenance and scope

outputs/deepreach/ preserves the original source, configs, dependency record, reports, experiment protocols and third-party notices byte for byte. Source hash guards remain active; no machine paths were rewritten inside frozen research records. Absolute paths in metadata describe the original machine, while the portable entry points resolve files from this package folder. The environment folder and Python bytecode caches are excluded.

package_manifest.json lists the original bytes, hashes and archive assignment for every file. downloads.json records optional ZIP hashes. The source is a standalone implementation; the upstream DeepReach repository is not redistributed. See outputs/deepreach/THIRD_PARTY_NOTICES.md for the SIREN notice and pinned upstream attribution.

The archived reports are historical records. Use the current public report for edited wording and the final interpretation: https://github.com/evl-jack/MAE_494_2026/blob/Main/Project_3.md. The 3D final evaluation was completed and consumed. The reserved future 6D final inputs have not been evaluated, and no command here generates or opens them.

This package does not claim paper-scale reproduction, exact numerical gradients, or certified collision avoidance. Timing varies with machine and environment. See VALIDATION.md for what was actually checked on this release.
